## 待修复问题

### QA-01 · P1 · 未提交笔画被定期保存覆盖，刷新后丢失

**范围：** 书写保存逻辑共用；本次在 390×844 实际复现。

**复现：** 自建“QA草稿恢复”，正文“一二三”；切换为手动点击走纸；第一字写一笔，保持在当前字不提交；等待超过 15 秒，再刷新并跳过仪式。

**实际：** 刷新前为“圆满 (1/1)”且可见墨迹；刷新后为“0/1笔”，画布只剩底稿，笔迹丢失。

**预期：** 落笔后保存的草稿在定期保存与刷新之后仍完整保留。

**依据：** [刷新前](qa-evidence/07-draft-before-reload.jpg)、[刷新后](qa-evidence/08-draft-after-reload.jpg)。`ZoomWritingPad.tsx:526` 附近逐笔写入数据库，但 `App.tsx:207` 的全量保存使用 `writtenChars`，该状态仅在 `handleCharComplete` 提交整字时更新；`App.tsx:229` 每 15 秒全量保存会覆盖数据库中的未提交笔画。

**修复验收：** 手动模式写多笔，跨过两轮定期保存后刷新，当前索引、笔画数和每一笔均保留；再提交并刷新也应一致。

### QA-02 · P1 · 清空已提交字后切换字格，旧笔迹重新出现

**范围：** 本次在 390×844 的心经第 1 字复现；撤销至空也使用同类状态更新路径。

**复现：** 写一笔并“写完走纸”→“回到上一字”→“重写”，确认变为 0 笔→“写完走纸”→“回到上一字”。

**实际：** 被清空的那一笔重新出现，计数恢复为“1/6笔”。

**预期：** 清空或撤销后的结果成为当前字的有效状态，导航、定期保存及导出不能恢复旧内容。

**依据：** [旧笔迹恢复](qa-evidence/03-cleared-stroke-returns.jpg)；操作前后计数记录见 `checks.txt`。`ZoomWritingPad.tsx:603` 清空本地状态和数据库，仅向父层更新 `liveStrokes`；`App.tsx:278` 返回字格时仍读取未更新的 `writtenChars`。空白走纸走 `ZoomWritingPad.tsx:619` 的 `onNextChar` 路径，不会重新提交空状态。

**修复验收：** 对已提交字分别测试清空、撤销一笔、全部撤销，再前后导航和刷新，保证画布、全景、历史及导出状态一致。

### QA-03 · P1 · 390 像素窄屏纸墨菜单越出右边界

**范围：** 390×844 顶栏“选择纸张古笺、墨色与笔触粗细”。

**复现：** 点击顶栏调色盘图标，等待展开动画结束。

**实际：** 面板右侧被裁切，关闭按钮、朱砂墨和榜书档位在屏幕外；古籍竹纸只露出一部分。用户无法正常访问全部设置。

**依据：** [窄屏菜单截图](qa-evidence/04-narrow-theme-menu-clipped.jpg)。DOM 实测屏幕右边界为 x=390，而关闭按钮 x=485.61～502、朱砂墨 x=409.33～502、榜书 x=431.50～502。相关位置：`TopZenCapsule.tsx:149` 的定位浮层；其祖先存在 transform，浮层也使用带 transform 的 `fade-in` 动画，需一并核查定位基准及平移是否被覆盖。

**预期／修复验收：** 在 320、390、768 像素宽度下，面板、关闭按钮、全部纸张、墨色与字号均位于视口内，能通过实际点击完成选择。

### QA-04 · P2 · 宽屏长卷仍只有 200 像素高

**范围：** 1440×900 开发页面与 1920×1080 生产页面均复现。

**实际：** 1440 宽屏左区高度 200，右区高度 836；1920 宽屏左区高度仍为 200，右区高度 1016。左区下方大量空白，八行模式被压缩成很小的字，宽屏空间利用明显不符合双区布局意图。

**依据：** [1440 宽屏](qa-evidence/01-wide-1440x900.jpg)、[1920 生产宽屏](qa-evidence/12-production-wide-1920x1080.jpg)及 `checks.txt` 的 DOM 测量。`App.tsx:420` 同时保留 `max-h-[200px]` 和宽屏 `h-full`，没有解除最大高度。

**预期／修复验收：** 横屏与桌面断点下长卷使用可用高度；验证大字、八行、全屏展开／返回及改变窗口尺寸，不能继续被手机布局的最大高度限制。

### QA-05 · P2 · 小手机底部走纸模式控件被裁切

**范围：** 320×568，生产构建复现。

**实际：** 走纸模式按钮与说明落到屏幕底部之外。实测按钮 y=553.14～574.14，超出 568 高的视口；页面 `overflow:hidden`，无法通过页面滚动完整查看。

**依据：** [稳定的小屏截图](qa-evidence/05-small-320x568.jpg)。相关布局：`App.tsx:409` 主区和 `ZoomWritingPad.tsx:808` 画布尺寸计算；固定预览区、画布及上下控制条的总高度超过可用空间。

**预期／修复验收：** 320×568 下完整显示当前字、书写台、撤销／重写／走纸和模式开关，或提供明确可滚动布局；同时回归 390×844，避免缩放后出现新遮挡。

### QA-06 · P2 · 手机横屏走纸设置顶部被遮挡／裁切

**范围：** 844×390。

**复现：** 打开书写台下方的走纸模式设置。

**实际：** 菜单向上展开后，标题、关闭入口及推荐选项上部不可完整查看；浮动顶栏又覆盖其上方区域。

**依据：** [横屏设置截图](qa-evidence/10-landscape-settings-clipped.jpg)。`ZoomWritingPad.tsx:957` 使用 `absolute bottom-full` 的固定宽度面板；书写区域祖先有 `overflow-hidden`，没有根据剩余高度调整展开方向或滚动范围。

**预期／修复验收：** 在 844×390 下打开设置，标题、关闭、三种模式与所有等待时长均可见、可点击；关闭后书写台继续正常工作。

### QA-07 · P2 · 多个设置面板实际没有背景色，文字与底图混叠

**范围：** 顶栏纸墨菜单、书写台笔触菜单、走纸设置共用相同背景类；生产 1440×900 笔触菜单实际复现。

**实际：** 浅色纸面上的菜单呈透明背景，浅色文字难读，画布内容透入菜单。不是单纯的层级被盖住。

**依据：** [生产笔触菜单](qa-evidence/14-brush-menu-transparent.jpg)。DOM 实测面板 `background-color: rgba(0, 0, 0, 0)`。`TopZenCapsule.tsx:149`、`ZoomWritingPad.tsx:724`、`:957` 使用 `bg-stone-900/98`，当前 Tailwind 配置未扩展 98% 透明度，实际未生成有效背景。

**预期／修复验收：** 三类菜单均有有效、足够遮盖底图的背景；在宣纸和磁青主题上检查标题、选项、数值与关闭按钮的可读性。

### QA-08 · P2 · 中等宽度顶栏纸墨名称纵向换行，遮住内容

**范围：** 768×1024、844×390 均复现。

**实际：** 顶栏“古法宣纸 · 20px/26px”被挤成多行，胶囊高度增长到约 90 像素，覆盖长卷工具栏；横屏时还遮挡书写台顶部指示区。

**依据：** [平板竖屏](qa-evidence/15-tablet-768x1024.jpg)、[手机横屏](qa-evidence/09-landscape-844x390.jpg)。`TopZenCapsule.tsx:110` 的胶囊容器与纸墨按钮缺少适合该断点的收缩／单行策略；主区仍只预留 `sm:pt-14`。

**预期／修复验收：** 640～1024 像素宽度范围内逐步调整窗口，顶栏保持可读且不覆盖主区；必要时隐藏次要文字，并为实际顶栏高度预留空间。

### QA-09 · P2 · 磁青主题下当前字及序号几乎不可读

**范围：** 390×844 实际复现；相关文字颜色不随主题变化。

**实际：** 背景切为深蓝后，书写台上方的当前字“观”和序号仍使用深色字，视觉上接近消失；画布内的金色底稿正常，外部状态栏未同步适配。

**依据：** [磁青主题截图](qa-evidence/02-narrow-390x844.jpg)。`ZoomWritingPad.tsx:639` 附近固定使用 `text-stone-700`、`text-amber-950`、`text-stone-900`，没有按深色纸张调整文字或承载背景。

**预期／修复验收：** 四种纸张下当前字、字序、笔画数和操作说明均清晰可读；对磁青与红笺分别进行截图回归。

### QA-10 · P2 · 印章实景预览首次为空白，切换标签后再次消失

**范围：** 320×568 的导出弹窗实际复现。

**复现：** 首次打开导出→观察默认“静心”预览→改为“测试”→预览正常出现→切到笔迹回放→切回钤印导出。

**实际：** 首次预览空白；修改文字可触发绘制；切换标签返回后预览再次空白，即使文本框仍为“测试”。

**依据：** [首次空白预览](qa-evidence/06-seal-preview-empty.jpg)。`SealAndExportModal.tsx:80` 的绘制 effect 只依赖 `sealText`、`sealStyle`；模态框开启或导出标签重新挂载 canvas 时，没有触发绘制。

**预期／修复验收：** 首次打开、重复开关弹窗、往返切换两个标签，印章预览始终与印文及风格一致，不需要额外编辑才能出现。

### QA-11 · P2 · 未写完整篇也显示已圆满，随后自动保存又撤回圆满状态

**范围：** 自建三字帖“一二三”，390×844 实际复现。

**复现：** 提交第 1 字→跳过第 2 字→第 3 字写一笔并点击“圆满结卷”→立即打开功德簿→经过下一轮自动保存，再关闭并重新打开功德簿。

**实际：** 首次显示“进度 2/3 字”“已圆满”“圆满长卷 1 部”；随后同一会话显示 2/3、已圆满标记消失，统计变回 0 部。完成状态既与实际覆盖字数不符，也不稳定。

**依据：** [错误判圆满](qa-evidence/11-incomplete-marked-finished.jpg)、[自动保存后标记消失](qa-evidence/13-finished-flag-lost-after-save.jpg)。`App.tsx:260` 仅按当前位置是否到末字判断完成；`persistSession` 常规保存未保留 `completedAt`。`localDb.ts:466` 又将 `completedAt` 或记录总数作为圆满依据。

**预期／修复验收：** 明确并统一“结卷”与“完成全篇”的规则；缺字的 2/3 不应计为完整 1 部。完整三字写完后，跨多轮保存、重新打开功德簿与刷新，圆满状态应保持一致。

### QA-12 · P2 · 生产 PWA 清单引用的两个应用图标没有交付

**验证方式：** 本次为构建产物与静态文件检查，未进行真机安装。

**实际：** 生成的 `manifest.webmanifest` 引用 `/pwa-192x192.png` 和 `/pwa-512x512.png`，但 `public/` 与本次完整生产构建中均无这两个文件。

**依据：** `vite.config.ts:25` 附近的 icons 配置、实际生成的 manifest 和构建文件清单，详见 [checks.txt](qa-evidence/checks.txt)。

**影响：** 应用声明的安装图标资源不存在，PWA 安装体验／图标要求无法验收；不能据此推断普通网页或全部离线功能失败。

**修复验收：** 产物包含尺寸及格式正确的图标；部署在预期根路径／子路径后资源地址均能取到真实 PNG，再进行目标 Android 浏览器安装、启动与离线刷新验证。
